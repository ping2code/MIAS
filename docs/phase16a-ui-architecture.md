# Phase 16A: UI architecture and requirements

This is the architecture and contract for the MIAS dashboard (`mias-ui`). It's documentation only: no frontend code,
no backend endpoints, no cluster changes.

The UI is a **presentation client** of the existing read-only `mias-api`. It never computes trading judgments,
never bypasses API contracts, and never touches PostgreSQL, Redis, the artifact PVC, collectors, the publisher, or
the Kubernetes/OpenShift APIs.

```
Browser ──HTTPS──▶ Route mias-ui ──▶ mias-ui (static files + same-origin proxy, no secrets)
                                        │  /api/v1/*, /health/*  (Authorization passed through, never added)
                                        ▼
                                  Service mias-api:8080 (ClusterIP) ──▶ immutable artifacts (read-only)
```

## 1. Frontend stack (selected)

**React 18+ with TypeScript, built by Vite into a static bundle.**

| Library | Why |
|---|---|
| `react`, `react-dom` | Component model; large ecosystem for testing and accessibility |
| `typescript` (strict) | Typed API client generated by hand from the Phase 13 view schemas |
| `vite` | Fast, simple static build; no server runtime |
| `react-router` | Deep links to `/market-intelligence/:id`, `/alerts/:id` and so on |
| `@tanstack/react-query` | **Justified:** polling intervals per query, request cancellation (AbortSignal), retry control by error class, a cache keyed by artifact id, and stale/refresh state. Hand-writing that would be more code and more bugs. |

Development only: `vitest`, `@testing-library/react`, `@testing-library/user-event`, `msw` (a mocked mias-api),
`eslint`, `typescript-eslint` and `@playwright/test` (16F, optional).

Node 22 LTS is used for builds (22.22 is available locally). No runtime Node.

## 2. Rejected alternatives

| Option | Why not |
|---|---|
| Next.js | SSR and a Node server runtime aren't needed for a read-only static client. It adds a server process, attack surface and image size. |
| Serving the UI from mias-api | Couples UI releases to the scientific API, adds static-file serving and a CSP surface to the Phase 13 locked service, and breaks independent rollout. |
| Redux / large component frameworks (MUI, Ant) | Not needed: state is server state (React Query) plus a little UI state. A big framework adds weight and theming lock-in. |
| Charting library now | No time-series endpoint exists (see §7). Defer until a chart has data. |
| WebSocket / SSE | Artifacts change at minute or hour cadence and the API has no push channel. Polling is enough (§10). |

## 3. Deployment topology (selected)

**A separate `mias-ui` workload:** Deployment, Service and Route in namespace `mias`, with its own image, digest and
release cadence. It serves static assets and a **same-origin reverse proxy** for `/api/v1/` and `/health/` to the
internal `mias-api` Service.

| Browser target | Decision |
|---|---|
| A. External mias-api Route (cross-origin) | Rejected: needs CORS with credentials on mias-api, which is a Phase 13 contract change, and a second TLS/DNS name. |
| **B. Same-origin proxy through mias-ui** | **Selected:** no CORS at all, one origin and certificate. mias-api keeps its locked contract, Route and auth. |
| C. UI server-side proxy that **holds** the token | Rejected: it would turn the mias-ui Route into an unauthenticated read API (§4). |

The existing `mias-api` Route stays for CLI and automation clients.

## 4. Auth and session model (interim, until OAuth/OIDC)

**Decision: the user supplies the read token at sign-in. The proxy passes `Authorization` through unchanged and
never stores or adds a token.**

- **Sign-in screen:** a password-type field. The token is validated by `GET /api/v1/version` (200 means accepted;
  401 means rejected).
- **Default storage:** **in-memory only**, in a React context and a module variable that are never logged. A page
  reload asks again.
- **Optional "Keep me signed in for this tab":** stores it in `sessionStorage` (scoped to the tab, cleared on close).
  `localStorage`, cookies and IndexedDB are never used.
- **Sign out:** clears memory and `sessionStorage`, and the React Query cache.
- **Any 401:** clears the token and returns to sign-in, with the attempted location preserved.
- **The token never appears in:**
  - source code;
  - Vite `import.meta.env` or any build-time variable;
  - ConfigMaps, Helm values, static assets or bundles;
  - URLs or query strings;
  - logs, telemetry, error screens or browser history.
- **Exposure:** a token in browser memory is exposed only to script running in the page. That's mitigated by a
  strict CSP: no inline script and no third-party origins (§14).

**Why not (C):** a proxy-held token would let anyone who reaches the UI Route read every artifact. That silently
removes the Phase 13 "non-loopback reads require authentication" guarantee.

**Future (not in Phase 16):** OpenShift OAuth proxy or OIDC in front of mias-ui. The API side would then accept a
service credential or a forwarded identity. This needs a separate API auth decision.

## 5. CORS

There are **no cross-origin requests**, because the UI and API share the mias-ui origin through the proxy. mias-api
keeps **no** CORS middleware, as Phase 13 locked. The UI never calls `*.apps` hosts other than its own, and never
calls external market data.

## 6. Pages and navigation

There's a persistent left navigation, every page has a deep-linkable URL, and the sign-in gate is shown when there's
no token.

| Route | Page |
|---|---|
| `/` | Overview |
| `/market-intelligence`, `/market-intelligence/:id` | Market Intelligence list and detail |
| `/alerts`, `/alerts/:id` | Alerts list and detail |
| `/options-intelligence`, `/options-intelligence/:id` | Options Intelligence |
| `/trade-setups`, `/trade-setups/:id` | Trade Setups |
| `/invalidation-checks`, `/invalidation-checks/:id` | Invalidation Checks |
| `/status` | System Status |

Kinds that are empty today (options intelligence, trade setups, invalidation checks) stay in the navigation and show
"No data available yet", not an error.

**Overview widgets (API-backed only):**
- API live and ready;
- the API build (`/api/v1/version` `build`) and the UI build;
- latest Market Intelligence;
- latest Alert;
- for each of the 5 kinds, **"has data / latest as_of"** from `GET /<kind>?limit=1`;
- "last refreshed" (UI clock).

**Total artifact counts are not shown**, because the API has no count endpoint and walking every page to count isn't
acceptable. That's a known gap (§22).

**Detail pages:** the summary view fields as labelled key/value rows, the artifact id (copyable), the sealed `as_of`,
a "Raw / Canonical" tab (§12), and the source references where the view has them (`alert.source_refs`;
`trade-setup.market_intelligence_id`/`options_intelligence_id`, linked).

**No derived judgments.** No buy/sell or score computed in the UI. Domain states such as `timeframe_pattern`, the
alert code, `outcome_status`, `result`/`reason` and `market_bias_state` are displayed **verbatim**, with neutral
styling (§21).

## 7. Endpoint inventory and screen mapping

These are all existing Phase 13 endpoints, unchanged. All `/api/v1` endpoints need `Authorization: Bearer`. Every
error uses the closed envelope `{"error": {"code", "message", "request_id"}}`.

| Method and path | Auth | Response | Paging | Relevant errors | Cache | Screen |
|---|---|---|---|---|---|---|
| `GET /health/live` | none | `{"status":"live"}` | — | (network) | no-store | Status, Overview |
| `GET /health/ready` | none | `{"status","checks":[{name,status}]}`, 200 or 503 | — | 503 = not ready | no-store | Status, Overview |
| `GET /api/v1/version` | bearer | `{service, api_version, build, analytical_formats[]}` | — | 401 | short | Sign-in check, Status |
| `GET /api/v1/{family}` (history) | bearer | `{data:[summary], meta:{api_version, view, request_id, served_at, limit, next_cursor}}` | cursor; `limit` 1–200 (default 50); `symbol`, `as_of_from`, `as_of_to` (RFC 3339 with offset) | 400 (bad params or cursor), 401, 503 | by query | List pages, Overview "latest as_of" |
| `GET /api/v1/{family}/latest?symbol=S[&as_of=T]` | bearer | `{data:summary, meta}` | — | 400 (no symbol), 401, 404 (none), **409 `ambiguous_latest`**, 503 | 30 s | Overview latest, list "latest" panel |
| `GET /api/v1/{family}/{id}` | bearer | `{data:summary, meta}` | — | 400 (bad id), 401, 404, 500 `artifact_invalid` | by id (immutable content) | Detail |
| `GET /api/v1/{family}/{id}/canonical` | bearer | exact stored bytes, `application/json`, `ETag: "<id>"`, `Cache-Control: private, max-age=31536000, immutable` | — | 401, 404, 500 `artifact_invalid` | **forever by id** | Detail, Raw tab |
| `GET /api/v1/alerts/{id}/deliveries` | bearer | `{data:[receipt], meta}` | — | **503 `dependency_unavailable`** (no receipt root in v1), 404, 401 | 60 s | Alert detail ("Delivery status unavailable"), never fabricated |

`{family}` is one of `market-intelligence`, `options-intelligence`, `trade-setups`, `invalidation-checks`, `alerts`.

**Summary view fields** used by the screens (Phase 13 locked):

| Family | Fields |
|---|---|
| Market Intelligence | `intelligence_id`, `symbol`, `as_of`, `timeframe_pattern`, `technical_status`, `market_context_available`, `conflict_codes`, `attention[{code, category}]` |
| Alerts | `alert_id`, `alert_code`, `symbol`, `subject_kind`, `assessment_id`, `transition{previous, current}`, `as_of`, `facts`, `source_refs[{role, object_kind, id}]` |
| Options Intelligence | `options_intelligence_id`, `symbol`, `as_of`, `snapshot_id`, `contract_count` |
| Trade Setups | `assessment_id`, `symbol`, `as_of`, `outcome_status`, `no_setup_reasons`, `market_bias_state`, `eligible_side`, `candidate_count`, MI/OI/policy ids |
| Invalidation Checks | `invalidation_id`, `symbol`, `as_of`, `result`, `reason`, `assessment_id`, `side`, `required_pattern`, `observed_pattern`, `observed_technical_status`, `market_intelligence_id` |

**Symbol selection:** there's no symbols endpoint. The symbol filter lists the distinct symbols on the history pages
already loaded, and offers a free-text field checked against the API's symbol rule (`[A-Z][A-Z0-9.\-]{0,9}`). "Latest"
needs a symbol; without one the page shows the newest history items instead.

## 8. API client contract (Phase 16B)

- **Base URL:** relative (`/api/v1`, `/health`), so it's always same-origin. No configurable absolute URL in the
  bundle.
- **Auth:** the client adds `Authorization: Bearer <token>` from the session store to `/api/v1/*` only, never to
  `/health/*`.
- **Request id:** each request sends a generated `X-Request-ID` (`ui-` plus 24 hex characters from
  `crypto.getRandomValues`, which matches `[A-Za-z0-9][A-Za-z0-9._-]{7,63}`). The client records the response's
  `X-Request-ID`, or the error body's `request_id`, on every result and error.
- **Timeout:** 10 s per request via `AbortController`. React Query cancellation aborts requests when navigating away.
- **Decoding:**
  - **views:** JSON into typed interfaces, rejecting unexpected shapes as `invalid_response`;
  - **canonical:** read as **text** (exact bytes, §12);
  - **errors:** parse the closed envelope, falling back to "unexpected response".
- **Retry policy:**
  - at most **2 retries** with backoff (1 s, then 3 s), **only** for network errors, timeouts, 502/503/504 and 500
    `internal`;
  - **never** for 400, 401, 403, 404, 405, 409 or 500 `artifact_invalid`.

| Status / code | UI behaviour |
|---|---|
| 401 `unauthorized` | Clear the token and go to sign-in: "Authentication required or token no longer valid". |
| 404 `not_found` | "Artifact not found" (detail) or "No data available yet" (latest or empty list). Not an error banner. |
| 409 `ambiguous_latest` | "More than one artifact shares the latest time for SYMBOL; showing history instead" plus a link to the filtered history. **The UI never picks one.** |
| 400 `invalid_request` | "The request was not accepted", shown inline at the input that caused it (bad symbol, time or cursor). |
| 500 `artifact_invalid` | "This stored artifact failed integrity verification", with the request id. Not retried. |
| 503 `dependency_unavailable` | "Service temporarily unavailable". For deliveries: "Delivery status is not available in this deployment". |
| 5xx / network / timeout | "MIAS API temporarily unreachable; retrying". After retries: an error panel with the request id and a Retry button. |
| readiness 503 | A global banner, "API not ready", with the failing check names only. Data already shown stays, marked "may be stale". |

Error UI never shows stack traces, headers, tokens or raw response bodies other than the closed error message, its
code and the request id.

## 9. Page states

Every data region has four explicit states, so there are no blank screens:
- **loading:** a skeleton rows/cards placeholder. A silent background refresh keeps the current data with a small
  "refreshing" indicator.
- **empty:** "No data available yet".
- **error:** the panel from §8, with code, message, request id and Retry.
- **loaded:** the data, with "as of …" and "last refreshed …".

## 10. Refresh strategy (polling, no push)

| Data | Interval | Notes |
|---|---|---|
| `/health/live`, `/health/ready` | 30 s | Paused when the tab is hidden |
| `/api/v1/version` | at sign-in, then 5 min | |
| `latest` per kind (Overview) | 30 s | |
| History lists | manual Refresh, plus 60 s on the **first page only** | Later pages aren't auto-refreshed, so cursor stability is kept |
| Detail summary by id | never re-polled (the content is immutable); refetch on demand | |
| Canonical by id | cached for the session, keyed by id; never refetched | |

React Query uses `refetchIntervalInBackground: false`, `refetchOnWindowFocus: true` (debounced) and a **staleTime**
equal to the poll interval.

The API doesn't support conditional requests (`If-None-Match`/304), so "respecting ETag" means **caching immutable
artifacts by id and never re-requesting them**. The browser HTTP cache also honours
`Cache-Control: immutable` for canonical responses.

## 11. Timestamps

- **Main display:** the user's local time zone, `YYYY-MM-DD HH:mm:ss` plus the zone abbreviation.
- **Tooltip and details:** the **original ISO string exactly as returned** (for example
  `2026-09-23T20:05:00+00:00`), plus UTC.
- **Three clearly labelled kinds:**
  - **as of:** the artifact's sealed time, never rounded or rewritten;
  - **served at:** the API's `meta.served_at`;
  - **last refreshed:** the UI's own clock.
- **Filter inputs** produce RFC 3339 **with an explicit offset**; the API rejects anything else.

## 12. Raw / Canonical view

- **Fetch:** `GET …/{id}/canonical`, read with `response.text()`, so the **exact bytes are kept**.
- **Display:**
  - the **Canonical** tab shows the exact text, monospace and scrollable;
  - an optional **Formatted** toggle pretty-prints a parsed copy, labelled "formatted view, not canonical".
- **Copy and Download:** always use the **original text** (`<id-hex>.json`).
- **Integrity check:** the UI also shows the `ETag` it received next to the id, and checks the ETag equals the id it
  requested.

## 13. UI security boundary

| | Allowed? |
|---|---|
| Browser → mias-ui origin (static files and proxied `/api/v1`, `/health`) | Yes; nothing else |
| mias-ui → `mias-api` Service :8080 | Yes; nothing else |
| PostgreSQL, Redis, PVC, publisher, collector, Prometheus, Kubernetes/OpenShift APIs, external market data | **Never** |

There are no write actions, no publish or delivery or trading endpoints, and no execution. The UI is read-only by
construction: the API exposes only GET.

## 14. Security headers (mias-ui web server)

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
  connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self';
  frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Cache-Control: no-store                                           (index.html)
Cache-Control: public, max-age=31536000, immutable                (hashed /assets/*)
```

- **No inline scripts or styles:** Vite is configured to emit no inline scripts, and there are no `style=` attributes
  generated at runtime.
- **No external assets:** no CDN fonts or scripts. Everything is bundled.
- **No server banner:** the `Server` header is hidden (`server_tokens off`).
- **Proxied API responses** keep mias-api's own headers.

## 15. Dependency policy

- **Runtime:** only the five in §1. Each extra runtime dependency needs a stated reason in its PR.
- **Pinning:** exact versions in `package.json` and a committed `package-lock.json`, installed with `npm ci`.
- **Checks:** `npm audit --omit=dev` is reviewed in 16F.
- **Not allowed:** CDN script tags, analytics or trackers, and anything that phones home.
- **Licences:** MIT/BSD/Apache only.

## 16. Container design (16B)

Multi-stage build:
1. **Builder:** Red Hat UBI 9 `nodejs-22` (pinned by digest). `npm ci`, then `npm run build` (typecheck, lint, Vite).
2. **Runtime:** Red Hat UBI 9 `nginx-124` (pinned by digest). It runs as a non-root user with an arbitrary UID in
   group 0 and listens on **8080**.
   - **Contents:** only `dist/` and an nginx config.
   - **Excluded:** Node, npm, source and source maps. Source maps are off in production builds, since the bundle
     holds no secrets but maps aren't needed.

**Read-only root filesystem:** nginx temp, cache and pid paths point to `/tmp` (an `emptyDir`); nothing else is
writable.

**Proxy configuration:** `/api/v1/` and `/health/` go to `http://mias-api.mias.svc:8080`. The `Authorization` and
`X-Request-ID` headers are passed through. There's no buffering of canonical bodies beyond defaults, a 15 s proxy
timeout, and no caching in nginx.

## 17. OpenShift design (16B/16C)

- **Workload:** Deployment `mias-ui`, 1 replica, using RollingUpdate. It's stateless with no PVC, so
  `maxUnavailable: 0` is possible.
- **Service and Route:** Service `mias-ui` (ClusterIP 8080) and a Route with edge TLS and a redirect.
- **Hostname:** the planned host is `mias-ui.apps.ngc.sirii.org`. It needs a DNS or hosts entry like the API's.
- **Identity:** ServiceAccount `mias-ui`, `automountServiceAccountToken: false`, no RBAC.
- **Security:** restricted-v2, `runAsNonRoot`, no fixed UID, `allowPrivilegeEscalation: false`, all capabilities
  dropped, seccomp RuntimeDefault, `readOnlyRootFilesystem: true`, and a `/tmp` `emptyDir`.
- **Probes:** liveness and readiness on a static `/healthz` served by nginx, so that UI health doesn't depend on the
  API.
- **Resources (starting values):** requests 10m/32Mi, limits 200m/128Mi.

## 18. NetworkPolicy design

- **mias-ui ingress:** from the router (`policy-group.network.openshift.io/ingress`) on TCP 8080 only.
- **mias-ui egress:** to `mias-api` pods on TCP 8080, plus cluster DNS (openshift-dns pods, UDP/TCP 5353) so nginx
  can resolve the Service name. That's the same pattern as the Phase 15 telemetry egress. Nothing else.
- **mias-api ingress (a chart change, not an API code change):** add a rule allowing `app.kubernetes.io/name: mias-ui`
  pods on TCP 8080, alongside the existing router rule.
- **Default deny:** mias-ui carries `app.kubernetes.io/part-of: mias`, so `mias-default-deny` applies.

## 19. Helm integration plan (16B+)

```yaml
ui:
  enabled: false                 # off until 16B delivers the image
  image: {repository: …/mias/mias-ui, digest: sha256:…, pullPolicy: IfNotPresent}
  replicaCount: 1
  route: {enabled: true, host: mias-ui.apps.ngc.sirii.org}
  resources: {…}
  api:
    mode: proxy                  # the only supported mode: same-origin proxy to the in-namespace Service
    upstream: http://mias-api.{{ .Release.Namespace }}.svc:8080
```

There's **no token value anywhere**, and no Secret for the UI. The new templates are the ServiceAccount, ConfigMap
(nginx config), Deployment, Service, Route and NetworkPolicies, plus the mias-api ingress rule. Tests extend
`tests/test_helm_*`: digest pinning, the security context, no token, narrow policies, and `ui.enabled=false` rendering
the Phase 15 set unchanged.

## 21. Accessibility, responsiveness and visual style

- **Accessibility:** WCAG 2.1 AA contrast; full keyboard navigation with visible focus; semantic tables
  (`<th scope>`); `aria-live` for refresh and error status; status shown with **text plus icon**, never colour alone.
- **Layout:** desktop-first (1920×1080 and 2560×1440), with dense, readable tables. Tablet collapses the navigation
  to a drawer. On phones, tables become stacked key/value cards (read-only inspection).
- **Style:** restrained and neutral. Domain values (patterns, outcomes, alert codes) are shown as **neutral labelled
  chips**. **No red/green buy/sell semantics**; colour signals only system health (ok, degraded, down) and errors.
- **Themes:** light and dark, following `prefers-color-scheme`, with a manual toggle.
- **Charts:** none in 16B–16E, because no time-series endpoint exists. Future candidates, once backed by data: an
  alert timeline from alert history and an intelligence-pattern timeline from MI history (client-side from paged
  history, bounded). There are no price charts and no external market data.

## Observability and status presentation

- **MIAS UI** shows a **lightweight status summary**: live and ready with check names, the API build and formats
  (`/api/v1/version`), the UI build, the time of the last successful fetch, and the request id of the last failure.
- **Deep operational metrics** (latency histograms, index refresh metrics, collector state) **stay in OpenShift
  monitoring** (UWM/Thanos). The UI doesn't query Prometheus, the collector or Kubernetes.
- **No browser telemetry** in Phase 16. A later browser OpenTelemetry SDK would need its own approval and a
  collector-ingress decision.
- **Correlation:** the request id is shown in error details for support. It's never a metric label.

## 22. Known limitations

- **No count endpoint:** per-kind totals aren't shown (only "has data / latest as_of").
- **No symbols endpoint:** symbol choices come from loaded history, plus free text.
- **No conditional requests (304):** immutable content is cached by id instead.
- **Deliveries:** return 503 in this deployment (no receipt root), so the UI shows "unavailable" and never infers
  status.
- **Interim auth:** a static shared token typed by the user. There's no per-user identity or audit, and rotation means
  everyone re-enters it. OAuth/OIDC is future work.
- **Lab TLS and DNS:** the self-signed ingress certificate and hosts-file DNS also apply to `mias-ui.apps…`.
- **Single API replica:** the API has a short outage on rollout (Phase 14), which the UI shows as "temporarily
  unavailable" and then recovers from automatically.

## 23. Phase 16B scope (exact)

**In scope:**
1. A `ui/` workspace: Vite + React + TypeScript (strict), eslint, vitest, MSW, with a committed `package-lock.json`.
2. A typed **API client** implementing §8 (auth injection, request id, timeout and abort, the retry matrix, error
   mapping, canonical-as-text) with full unit tests.
3. A **session store** (§4): memory by default, optional sessionStorage, cleared on 401 and sign-out. A **sign-in
   screen** validated by `/api/v1/version`.
4. A **dashboard skeleton:** the router with all §6 routes, the navigation shell, the shared page-state components
   (§9), and the **Overview** and **System Status** pages wired to live endpoints. Other pages are placeholders with
   working empty states.
5. The **container** (§16), validated with Podman (arbitrary UID, read-only root, headers, proxy pass-through).
6. A **Helm** `ui.*` block (§19), rendered but `ui.enabled=false` by default, with tests. **No cluster deployment in
   16B**, unless explicitly approved.

**Out of scope for 16B:** the full Market Intelligence and Alert views (16C); observability/status depth (16D);
auth/UX hardening (16E); OpenShift deployment and final validation (16F); charts, OIDC, browser telemetry, and any
backend change.

**16B acceptance:**
- `npm ci && npm run typecheck && npm run lint && npm test && npm run build` pass.
- The bundle contains no token or external URL.
- The container matrix passes.
- Helm tests pass, and the Phase 15 render is unchanged with `ui.enabled=false`.
- The full Python regression shows no new failures.
